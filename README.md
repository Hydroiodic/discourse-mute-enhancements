# discourse-mute-enhancements

免打扰增强。原名 discourse-search-tag-filter，功能变多后改了名字，设置名也从 `search_tag_filter_*` 改成了 `mute_enhancements_*`。

1. [搜索](#搜索)：用户设为免打扰或忽略的标签、类别、用户、话题，在搜索结果里看不到——既不出现它们的话题和帖子，也不出现在结果的用户、类别、标签部分，搜索框里输入 `@`、`#` 时也不会联想出它们。
2. [隐藏群组的 group_users](#隐藏群组的-group_users)：用户资料接口不再暴露用户看不到的群组的 ID。
3. [免打扰和忽略群组](#免打扰和忽略群组)：用户可以把整个群组设为免打扰或忽略，群组成员随之被免打扰或忽略。
4. [群组默认屏蔽的用户和群组](#群组默认屏蔽的用户和群组)：管理员可以给群组设置默认免打扰、忽略的用户和群组，新成员加入时自动生效。群组默认免打扰的类别和标签用核心自带的功能。
5. [对群组成员隐藏个人设置页面](#对群组成员隐藏个人设置页面)：管理员可以让群组成员看不到个人设置的“通知”“跟踪”“用户”页面。
6. [给群组成员屏蔽的话题](#给群组成员屏蔽的话题)：管理员填写话题 ID，群组所有成员（包括以后加入的）对这些话题的通知级别设为免打扰。
7. [给群组成员打开增强屏蔽](#给群组成员打开增强屏蔽)：管理员可以给群组成员（包括以后加入的）打开 [enhanced-ignore](https://github.com/ShuiyuanSJTU/enhanced-ignore) 插件的两个增强屏蔽选项。

4 到 7 都在群组 → 管理 → [用户偏好](#群组的用户偏好页面)里。

## 搜索

隐藏的内容：

- 带有用户已设为免打扰的标签的话题；
- 用户已设为免打扰的类别里的话题；
- 用户已设为免打扰的话题；
- 用户已忽略或已设为免打扰的那些用户发的帖子，以及他们创建的话题；
- 搜索结果的用户、类别、标签部分里的这些用户、类别、标签；
- 搜索框里输入 `@`、`#` 时联想出的这些用户、类别、标签，以及完整搜索页“用户”“类别/标签”类型里的它们，见[联想](#联想和完整搜索页的用户类别标签类型)。

顶部的快速搜索、完整搜索页、分页、`in:all`、`in:all-posts`、`order:` 等都会过滤；discourse-ai 的语义搜索（AI 搜索结果、AI 快速搜索）也会过滤。

### 通用规则

以下情况都不过滤：

- 在话题内搜索。
- 私信，包括 `in:messages` 和 `in:all` 结果里的私信。
- 匿名搜索。话题列表会对匿名用户应用 `default_tags_muted`、`default_categories_muted`，这里不应用：水源开启了 `login_required`，匿名搜索只来自站内的程序调用（例如 discourse-ai 的搜索工具），不应该因此少掉这些话题。

直接输入话题编号或链接搜索时，仍会返回那个话题。

### 免打扰的标签

话题只要带有用户设为免打扰的任何一个标签，就隐藏。以下情况不隐藏话题：

- 用户在搜索里明确要求的标签：在标签页内搜索（搜索上下文是这个标签）、`tags:`/`tag:` 过滤器（含同义词、`,` 和 `+` 写法）、`#标签` 和 `#标签组` 过滤器。只有这些标签不隐藏，话题上其他免打扰的标签照常生效。
- 用户关注了话题所在的类别，并且在个人设置里选择了“关注优先于免打扰”（`watched_precedence_over_muted`），和话题列表的行为一致。

“带有任何一个免打扰标签就隐藏”对应核心 `remove_muted_tags_from_latest` 的 `always`（默认值），不跟随这个设置变化。

搜索结果的标签部分不显示免打扰的标签，没有例外。

### 免打扰的类别

隐藏范围和话题列表一致（核心的 `CategoryUser.muted_category_ids`）：

- 用户设为免打扰的类别；
- 这些类别的子类别，除非用户给子类别单独设置了其他级别；
- 打开 `mute_all_categories_by_default` 时，用户没有设置过级别的所有类别。

以下情况不隐藏话题：

- 搜索明确指定了类别：在类别页内搜索、`category:`/`categories:` 过滤器、`#类别` 过滤器。这时整个指定范围（包括子类别）都显示。
- 用户单独跟踪或关注了这个话题，和话题列表一致。
- 话题带有用户关注的标签，并且用户选择了“关注优先于免打扰”，和话题列表一致。

搜索结果的类别部分不显示这些类别，没有例外。

### 免打扰的话题

话题的通知级别是“免打扰”时，整个话题（包括里面的回复）都不出现在搜索结果里，包括[群组给成员屏蔽的话题](#给群组成员屏蔽的话题)。核心的搜索默认不排除这些话题（只有 `in:watching`、`in:tracking` 这种主动筛选），话题列表才会排除。

以下情况不隐藏：

- 在这个话题内搜索，包括用 `topic:话题编号` 过滤器（核心会把它当作在话题内搜索）。
- 直接输入话题编号或链接搜索（见上面的通用规则）。
- 把通知级别改回别的级别之后。

### 忽略和免打扰的用户

隐藏用户已忽略、已设为免打扰的那些用户发的帖子，以及他们创建的话题（包括别人在里面的回复：搜索结果会显示话题标题，标题是这些用户写的）。管理员和版主不会被隐藏：忽略的名单来自核心的 `IgnoredUser.ignored_ids_for`，和话题页隐藏帖子用的是同一个；免打扰的名单按同样的规则排除管理人员。

注意这比话题页严格：Discourse 里“免打扰”只屏蔽通知和私信，话题页仍会显示他们的帖子，只有“忽略”才会隐藏；搜索里两者都隐藏。可以用 `mute_enhancements_search_muted_users` 关掉免打扰用户这部分。

以下情况不隐藏帖子：

- 搜索明确指定了这个用户：`@用户名`、`user:用户名` 过滤器，或在用户的个人活动页内搜索。只对指定的用户生效，其他被忽略或免打扰的用户照常隐藏。

搜索结果的用户部分不显示这些用户（管理员和版主除外），没有例外。

### 联想和完整搜索页的“用户”“类别/标签”类型

搜索框（顶部的搜索菜单和完整搜索页的输入框）里输入 `@` 或 `#` 时弹出的用户、类别、标签联想不经过 `Search`：用户和标签分别查 `/u/search/users`、`/tags/filter/search`，类别在浏览器里查。完整搜索页的“用户”“类别/标签”类型也是用这几种方式查的，不是 `Search` 的结果。插件让它们和搜索结果的用户、类别、标签部分一样：

- 不出现忽略、免打扰的用户，管理员和版主除外。`@` 后面还没输入时列出的最近活跃用户也一样。
- 不出现免打扰的类别，范围同上（包括子类别和 `mute_all_categories_by_default`）。
- 不出现免打扰的标签。
- 没有例外；跟随下面的 `mute_enhancements_search_*` 设置。匿名用户不过滤。

发帖编辑器和聊天里的 `@` 提及、`#` 联想，用户和标签选择框（例如私信收件人、话题的标签、完整搜索页高级搜索里的选择框），以及用户名录（`/u`），仍然列出所有人和所有类别、标签，以免想提及、选择的时候找不到。

### 实现

把 `DiscourseMuteEnhancements::SearchExtension` prepend 到 `::Search` 上：

- 覆盖 `Search#apply_filters`：先调用 `super`，再依次加上四个过滤器的条件（`MutedTagsFilter`、`MutedCategoriesFilter`、`MutedTopicsFilter`、`IgnoredUsersFilter`）。核心在 `Search#posts_query` 里调用 `apply_filters`，所有搜索帖子和话题的路径都经过这里；discourse-ai 的语义搜索也对自己的查询调用它。
- 覆盖 `user_search`、`category_search`、`tags_search`：在 `User`/`Category.where.not(id: ...).scoping { super() }` 里调用核心的方法，不复制核心的查询。`category_search` 进入 scoping 之前先算好 `secure_category_ids`，因为 Guardian 会缓存它，而它本身要查 `Category`。标签用 `Tag.where("tags.id NOT IN (?)", ...)`：核心的 `Tag.visible` 会 `merge` 一个自带 `tags.id` 条件的查询，`merge` 会替换掉同一列上已有的条件，写成 SQL 字符串才不会被丢掉。

为了判断用户明确要求了哪些标签和用户，`tags:`、`#`、`user:`、`@` 过滤器的正则和分词方式复制自核心 `lib/search.rb`；类别是否被明确指定，直接用核心过滤器设置的 `@category_filter_matched`（核心用它来显示搜索优先级为“忽略”的类别）。核心改动这些过滤器时需要同步。

联想用的接口发帖编辑器、聊天、选择框也在用，而且聊天里的 `@` 提及发出的参数和搜索框完全一样，服务器分不出来。所以由浏览器标记来自搜索的请求（`assets/javascripts/discourse/lib/search-suggestions.js`），服务器只过滤带标记的请求（`lib/discourse_mute_enhancements/search_suggestions.rb`）：

- 来自搜索的请求：焦点在搜索框里（`.search-menu-container`、`.search-bar__field`）时发出的；或者完整搜索页正按“用户”“类别/标签”类型搜索，而请求的关键词就是页面的搜索词（插件在 `full-page-search` 控制器的 `_search` 里记下搜索词）。
- 用户和标签：用 `$.ajaxPrefilter` 给这两个接口的请求加上 `mute_enhancements_search=true`。服务器把 `UsersControllerExtension` prepend 到 `UsersController`，在 `User.where.not(id: ...).scoping { super() }` 里调用核心的 `search_users`（`UserSearch` 的查询都从 `User` 开始）；把 `TagsControllerExtension` prepend 到 `TagsController`，把免打扰的标签加进 `selected_tag_ids`，核心本来就会把已选的标签排除在结果外。带 `filterForInput` 的请求（标签选择框）不加：这时 `selected_tag_ids` 还会被当作父标签、影响标签组“每个话题只能选一个”的规则。
- 类别：包装 `Category.search`，多取一些再去掉免打扰的类别。插件 API 没有修改模型静态方法的办法，`modifyClass` 用在模型上也已弃用，所以直接替换。免打扰的类别取自核心发给浏览器的 `muted_category_ids`、`indirectly_muted_category_ids`，用户修改类别级别时会即时更新；`mute_all_categories_by_default` 带来的那部分不在这两个列表里，插件另外在当前用户上加了 `mute_enhancements_default_muted_category_ids`，这部分刷新页面后才更新。
- 浏览器按参数把用户联想的结果缓存 30 秒，搜索框和聊天提及的参数相同，所以焦点进出搜索框时清空这个缓存，免得一边用上另一边的结果。

已知不覆盖：discourse-image-enhancement 的“图片”搜索标签页走自己的 `/image-search/search` 接口，不经过 `Search`，结果里仍可能出现这些内容。

## 隐藏群组的 group_users

把群组的可见性设为“群组拥有者”（或对非管理人员设为“工作人员”）后，成员在前端看不到这个群组，`/u/用户名.json` 的 `groups` 也不会列出它。但同一个接口里的 `group_users` 列出用户所在的全部群组的 ID 和通知级别，用户本人能看到，等于暴露了自己在一个看不到的群组里。

插件把 `UserSerializer#group_users` 限制为 `Group.visible_groups(查看者)`，和 `groups` 的规则一致。管理员仍能看到全部。群组拥有者能看到自己拥有的群组，所以拥有者的列表里仍有它。

要让成员完全察觉不到某个群组，群组本身还要这样设置：可见性和成员可见性都是“群组拥有者”，提及和发消息设为“没有人”，不设头衔、主要群组、徽章图标、信任等级和默认通知级别（这些都会在成员身上显示出来），添加成员时不勾选通知。

## 免打扰和忽略群组

个人设置 → 用户 页面多了“忽略的群组”和“免打扰的群组”两项。选中一个群组，就相当于把它的每个成员都单独设为忽略或免打扰：插件直接写核心的 `ignored_users`/`muted_users` 记录，所以核心对忽略、免打扰用户的所有处理（通知、私信、聊天、话题页隐藏帖子、上面的搜索过滤）都自动生效。

- 只能选能看到成员的群组（`visible_groups` 和 `members_visible_groups`），不能选自动群组（信任等级、工作人员、所有人）。管理员设置的[默认屏蔽的群组](#默认屏蔽的群组)可以是隐藏的群组，这时成员的列表里会出现自己选不到的群组。
- 管理员和版主不会被忽略或免打扰，和核心一致；自己也不会。
- 以后加入群组的成员自动生效，退出群组、成为管理人员的成员自动取消。成员变化时立即更新；另有每天一次的任务（`Jobs::MuteEnhancementsReconcileGroupMutes`）兜底，例如处理成员被提升为版主的情况。
- 忽略的有效期是“永久”（和核心忽略对话框里的“永久”一样是 1000 年后），直到取消群组。这些记录不计入核心通知版主“某用户被很多人忽略”的统计（`Jobs::IgnoredUsersSummary`）。
- 一个群组只能是忽略或免打扰之一。和核心一样，已经忽略的人不会再额外设为免打扰。

插件另外用一张表（`mute_enhancements_derived_mutes`）记住哪些记录是群组带来的：

- 用户之前自己设置过的免打扰、忽略不受影响，取消群组时也不会被删掉。
- 群组带来的记录不出现在“免打扰的用户”“忽略的用户”列表里，列表只显示自己单独设置的人；保存页面时插件会保留这些记录。
- 在用户卡片上把群组里的某个人单独改回“正常”，这个人会一直保持正常，直到取消再重新选择这个群组。
- 把群组里的某个人加进“免打扰的用户”列表，他就算自己单独设置的了，以后取消群组也仍然免打扰。

关闭 `mute_enhancements_group_mutes` 后，已经生成的记录保留，只是不再随成员变化更新，个人设置里也不再显示这两项。

## 群组的“用户偏好”页面

插件在群组 → 管理 里加了一个“用户偏好”标签，紧跟在“成员资格”后面，里面是下面四节的设置：[群组默认屏蔽的用户和群组](#群组默认屏蔽的用户和群组)、[对群组成员隐藏个人设置页面](#对群组成员隐藏个人设置页面)、[给群组成员屏蔽的话题](#给群组成员屏蔽的话题)和[给群组成员打开增强屏蔽](#给群组成员打开增强屏蔽)。

- 只有网站管理员能看到这个标签；群组拥有者和版主看不到，直接打开它的地址会转到“资料”。自动群组没有这个标签。
- 核心没有给群组管理页加标签的插件接口，插件改写了核心 `controller:group.manage` 的 `tabs`，并给 `/g/群组名/manage/user-preferences` 加了服务端路由。

## 群组默认屏蔽的用户和群组

需求是“给一个群组的所有成员设置免打扰、屏蔽的用户、类别、标签，新加入的成员也默认带上”，后来又加上了群组，和[免打扰和忽略群组](#免打扰和忽略群组)相对应。

- **类别和标签**：核心已经支持，直接用。群组 → 管理 → 类别 / 标签 页面可以设置成员默认的类别、标签通知级别，其中有“免打扰”。新成员加入时自动应用；保存时会询问是否同时应用到现有成员。注意核心只会提高级别：成员自己已经设置过这个类别或标签的，不会被改成免打扰。
- **用户和群组**：核心没有，官方也没有插件，由本插件实现。群组 → 管理 → 用户偏好 页面的“新成员默认屏蔽的用户和群组”，分“忽略的用户”“忽略的群组”“免打扰的用户”“免打扰的群组”四栏，有单独的保存按钮。只有管理员能看到和修改；群组拥有者和版主不能（核心允许群组拥有者修改默认的类别、标签级别，这里更严格）。

### 默认屏蔽的用户

默认屏蔽的用户和核心的类别、标签默认值行为一致：

- 用户加入群组时，给他写入自己的 `muted_users`/`ignored_users` 记录。他自己已经设置过这个人（免打扰或忽略）的，不改动。
- 这些记录属于成员自己，出现在他的列表里，可以自己取消。退出群组、管理员删掉某个默认用户，都不会撤销已经写入的记录。
- 新增默认用户后保存时，弹出和核心相同的对话框，询问是否同时应用到现有成员。
- 管理员和版主不能作为默认用户，保存时会报错。自动群组没有这一项。
- 每次保存都会记一条管理日志（“修改群组默认屏蔽的用户和群组”），列出保存后的默认用户和默认群组。
- 忽略的有效期同样是“永久”，同样不计入 `Jobs::IgnoredUsersSummary` 的统计。

### 默认屏蔽的群组

成员加入时，插件替成员把这些群组设为忽略或免打扰，等于成员自己在 个人设置 → 用户 里选了这个群组（写入成员自己的 `mute_enhancements_group_mutes` 记录），所以之后那个群组的成员变化（有人加入、退出、成为管理人员）都会跟着生效，规则见[免打扰和忽略群组](#免打扰和忽略群组)。其余和默认屏蔽的用户一致：

- 成员已经免打扰或忽略了这个群组的（不论哪一级），不改动。
- 这个设置属于成员自己，出现在成员的“忽略的群组”“免打扰的群组”里，可以自己取消。退出群组、管理员删掉某个默认群组，都不会撤销。
- 新增默认群组后保存时，同样询问是否应用到现有成员。提示里的人数按成员算，同时得到默认用户和默认群组的成员只算一次。
- 不能选自动群组和这个群组本身，否则保存时报错。
- 隐藏的群组（成员自己在个人设置里选不到的）也可以选。这是有意的取舍：管理员本来就能看到所有群组，而成员会因此知道这个群组，会在自己的“忽略的群组”“免打扰的群组”里看到它的名字，也能从被屏蔽的人（用户卡片上显示已忽略或免打扰、帖子被隐藏）推出群组里有谁。不想让成员知道的隐藏群组，就不要设为默认屏蔽。
- 成员可以自己取消隐藏的群组，但取消后个人设置里选不到它，自己加不回来。
- 同一个人既是默认屏蔽的用户、又在默认屏蔽的群组里时，先按默认用户设置的级别写入；如果默认用户是免打扰、群组是忽略，成员会同时免打扰并忽略这个人，和成员自己这样设置时一样。
- 和默认屏蔽的用户一样，不检查成员的信任等级是否达到免打扰、忽略别人所需的级别。
- 需要同时打开 `mute_enhancements_group_mutes`。关掉它时页面上不显示这两栏，保存也不改动已有的默认群组。

默认群组存在 `mute_enhancements_group_default_groups` 表里（`DiscourseMuteEnhancements::GroupDefaultGroups`），群组或被选的群组删除时一并删除。

配合[隐藏群组](#隐藏群组的-group_users)，可以把一批用户悄悄放进一个隐藏群组，让他们默认屏蔽某些用户、群组、类别、标签。被屏蔽的群组也可以是隐藏的，但成员会知道它的名字和成员（见上）。

## 对群组成员隐藏个人设置页面

群组 → 管理 → 用户偏好 页面的“对成员隐藏的个人设置页面”有三个复选框，“通知”“跟踪”和“用户”，分别设置，默认都不勾选。勾选的页面，这个群组的成员在个人设置里看不到：顶部标签栏和侧边栏的用户导航里都不显示，直接打开它的链接会转到“账户”。

- “通知”页面是通知的方式（点赞通知频率、桌面推送、通知时间表等），以及插件加在这里的选项，例如 enhanced-ignore 的增强屏蔽；和[给群组成员打开增强屏蔽](#给群组成员打开增强屏蔽)一起用时，成员就不能在界面上关掉这两个选项。“跟踪”页面是类别、标签的通知级别和话题跟踪设置；隐藏它时，单独的旧标签页（`/u/用户名/preferences/tags`）也一起隐藏。“用户”页面是免打扰、忽略的用户和群组。
- 成员在多个群组里时，隐藏的是这些群组勾选的页面的并集。
- 改动立即保存，并记一条管理日志。成员刷新页面后生效。
- 管理员和版主即使在群组里也不受影响，避免管理人员把自己锁在外面。
- 只是隐藏页面：页面上已有的设置照常生效，服务端也照常接受修改，成员仍能在别处修改，例如在用户卡片上忽略或免打扰别人、在类别和标签页面改通知级别。
- 隐藏的页面存在群组的自定义字段 `mute_enhancements_hide_preferences` 里，逗号分隔（`DiscourseMuteEnhancements::HiddenPreferences`）。这个功能最早只有一个开关，同时隐藏“通知”和“用户”，存的是 `t`；迁移会把它改成只隐藏“用户”，之后“通知”又作为单独的一项加了回来。

## 给群组成员屏蔽的话题

群组 → 管理 → 用户偏好 页面的“给成员屏蔽的话题”是一个文本框，每行填一个话题 ID（空格、逗号分隔也可以），有单独的保存按钮。

- 保存时，新加进来的话题对群组所有现有成员设为免打扰（核心话题通知级别里的“已设为免打扰”），不管成员原来是什么级别，包括关注。已经在列表里的话题不会再改一次，所以成员自己改回去后，管理员改动列表里别的话题不会把它重新设为免打扰；要强制重新设置，先删掉这个话题保存，再加回来保存。
- 以后加入群组的成员，加入时列表里的话题都设为免打扰。
- 成员可以在话题页面自己改回来。退出群组、从列表里删掉话题，都不会撤销已经设好的免打扰。
- 写入时用的是核心的“用户自己修改”（`user_changed`）原因，和成员自己在话题页面设为免打扰一样，所以之后关注这个话题所在的类别或标签不会把它改掉。
- 只能填未删除的话题，不能填私信；有填错的，整个列表都不保存，并提示哪些不对。
- 只有管理员能看到和修改，保存时记一条管理日志（列表有变化时）。
- 话题 ID 存在群组的自定义字段 `mute_enhancements_muted_topics` 里，逗号分隔（`DiscourseMuteEnhancements::GroupMutedTopics`）。

## 给群组成员打开增强屏蔽

[enhanced-ignore](https://github.com/ShuiyuanSJTU/enhanced-ignore) 插件在 个人设置 → 通知 里有“增强屏蔽”两个选项，默认关闭，要用户自己勾选：“不在我的主题列表中显示被屏蔽用户发表的话题帖”（最新、新话题、未读、类别、标签等话题列表里不再出现用户忽略的人发的话题），“被屏蔽用户不能回复我的话题帖”（被忽略的人不能回复用户发的话题，帖子数达到 `disable_topic_cannot_reply_threshold` 的话题除外）。

群组 → 管理 → 用户偏好 页面的“增强屏蔽”照搬这两个选项，“不在成员的主题列表中显示被屏蔽用户发表的话题帖”和“被屏蔽用户不能回复成员的话题帖”，分别设置，默认都不勾选，改动立即保存。

- 勾上一项时，所有现有成员的这一项都打开，包括自己关掉过的；已经勾着的不会再改一次。以后加入群组的成员，加入时群组勾选的选项都会打开。
- 成员可以在 个人设置 → 通知 里自己关掉。取消勾选、退出群组，都不会关掉已经打开的选项。要让成员在界面上关不掉，再对成员[隐藏“通知”页面](#对群组成员隐藏个人设置页面)。
- 被忽略的用户包括群组默认忽略的用户和群组成员（见[群组默认屏蔽的用户和群组](#群组默认屏蔽的用户和群组)），所以两者一起用，可以让群组成员在话题列表里看不到指定用户的话题、也不让他们回复。直接打开话题时仍能看到首帖，这是核心的行为。
- 需要安装并打开 enhanced-ignore（`enhanced_ignore_enabled`），否则页面上没有这一节，插件也不会改用户的选项。
- 只有管理员能看到和修改，改动时记一条管理日志。
- 写的是 enhanced-ignore 的用户自定义字段 `hide_ignored_topics` 和 `ignored_user_cannot_reply_to_me`；群组勾选的选项存在群组的自定义字段 `mute_enhancements_enhanced_ignore` 里，逗号分隔（`DiscourseMuteEnhancements::GroupEnhancedIgnore`）。

## 设置

- `mute_enhancements_enabled`：总开关，默认打开。
- `mute_enhancements_search_muted_tags`：搜索里隐藏免打扰的标签，默认打开。另外需要打开核心的 `tagging_enabled`。
- `mute_enhancements_search_muted_categories`：搜索里隐藏免打扰的类别，默认打开。
- `mute_enhancements_search_muted_topics`：搜索里隐藏免打扰的话题，默认打开。
- `mute_enhancements_search_ignored_users`：搜索里隐藏忽略的用户，默认打开。
- `mute_enhancements_search_muted_users`：搜索里隐藏免打扰的用户，默认打开。
- `mute_enhancements_hide_invisible_group_users`：`group_users` 只列出看得到的群组，默认打开。
- `mute_enhancements_group_mutes`：允许用户免打扰、忽略群组，默认打开。
- `mute_enhancements_group_default_users`：允许管理员设置群组默认屏蔽的用户和群组（群组还需要打开 `mute_enhancements_group_mutes`），默认打开。
- `mute_enhancements_group_hide_preferences`：允许管理员对群组成员隐藏个人设置的“通知”“跟踪”“用户”页面，默认打开（每个群组仍默认不隐藏）。
- `mute_enhancements_group_muted_topics`：允许管理员给群组成员屏蔽话题，默认打开。关闭后，已经设好的免打扰保留，新成员加入时不再设置。
- `mute_enhancements_group_enhanced_ignore`：允许管理员给群组成员打开 enhanced-ignore 的增强屏蔽选项，默认打开，需要 enhanced-ignore。关闭后，已经打开的选项保留，新成员加入时不再打开。

## 安装

按 Discourse 插件的通常方式安装：https://meta.discourse.org/t/install-a-plugin/19157

插件有数据库迁移（四张 `mute_enhancements_*` 表），安装后重建容器时会自动执行。
